# Кавалер (KavalerQt)

Каталог государственных наград Беларуси: база награждений в SQLite, интерфейс на Qt 6.
Импорт указов из Word (docx), перевод с белорусского через Яндекс.Переводчик.

## Сборка

Нужны:

- Visual Studio 2022 или 2019 16.7+ (MSVC, x64); VS 2017 не подходит для Qt 6;
- Qt 6.8 (`msvc2022_64`) с модулями Widgets, Sql, Network, PrintSupport;
- CMake 3.16+.

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH=C:/Qt/6.8.3/msvc2022_64
cmake --build build --config Release
```

Папка для запуска на машине без Qt и Visual Studio:

```bash
cmake --install build --config Release --prefix D:/Kavaler
```

В неё попадают `Kavaler.exe`, библиотеки Qt, среда выполнения MSVC и плагины в `plugins`:
драйвер SQLite, TLS для перевода через Яндекс, печать. Папку можно просто скопировать.
База и словари должностей лежат отдельно, путь к базе программа запоминает.

## Тесты

Тесты парсера указов (Qt Test) собираются вместе с проектом. Отключить их можно опцией
`-DKAVALER_BUILD_TESTS=OFF`. Запуск:

```bash
ctest --test-dir build -C Release --output-on-failure
```

| Тест | Что проверяет |
|------|---------------|
| `tst_textutil` | даты в заголовках указов, строковые утилиты |
| `tst_nameconverter` | ФИО из дательного/винительного падежа в именительный (рус./бел.) |
| `tst_professionconverter` | должности по словарям профессий, новые слова |
| `tst_documentparser` | награды, звания, «посмертно», форматы списков, сведения о группе |
| `tst_decrees` | реальные указы из `tests/data/decrees` против записей каталога |
| `tst_docxtext` | чтение docx (встроенный в Qt `QZipReader`) |
| `tst_catalog` | каталог на временной базе: поиск дубликатов, латинская «i» в белорусских полях, одно белорусское ФИО с разными русскими, резервная копия |
| `tst_translator` | перевод через Яндекс на локальном сервере-заглушке: несколько человек в запросе, одно соединение, ошибка и отмена посередине |

В `tests/data/decrees` лежат тексты указов (`<id>.txt`, `\v` означает разрыв строки
Word) и ожидаемые записи (`<id>.expected.tsv`) в том виде, в котором они хранятся в
каталоге. Если в колонке `known_issue` записано описание ошибки, тест ждёт
расхождения (`XFAIL`). Когда парсер исправят, тест сообщит `XPASS`, и пометку нужно
будет убрать. Словари профессий и таблица наград для тестов скопированы в `tests/data`,
настройки пользователя тесты не читают.

## Проверка парсера на всём архиве указов

`decree_report` разбирает все указы архива тем же кодом, что и окно импорта, и сравнивает
результат с каталогом по тем же правилам: указ, награда, ФИО без учёта латинских
двойников, однофамильцы по порядку. База открывается только на чтение, весь архив
(~2700 файлов) разбирается примерно за 7 секунд.

```bash
build/tools/Release/decree_report --db D:/Awards/DB/Kavaler.sqlite --docs D:/Awards/AwardsDoc --out build/reports/<дата>
build/tools/Release/decree_report --db D:/Awards/DB/Kavaler.sqlite --docs D:/Awards/AwardsDoc --out build/reports/<новая> --compare build/reports/<прошлая>
build/tools/Release/decree_report --names --db D:/Awards/DB/Kavaler.sqlite --out build/reports/names
```

`--names` смотрит только базу: одно белорусское ФИО и несколько русских написаний.
Указы не читаются. В `names.tsv` строки групп, в `summary.txt` сколько групп и записей.
Пустой список значит, что таких расхождений нет.

В папке отчёта:
- `summary.txt` — итоги, по годам, по полям, сравнение с прошлым прогоном;
- `persons.tsv` — люди, которые расходятся с каталогом: статус, запись каталога и ФИО
  в том виде, как оно написано в указе (`source_name`, падеж в `source_case`).
  Совпавшие полностью (`EXACT`) не пишутся, с `--all` пишутся все;
- `files.tsv` — по файлам указов, в `exact_index` номера совпавших людей
  (`0-12,14`): по ним `--compare` видит, кто раньше совпадал;
- `changes.tsv` — с `--compare`: у кого изменился статус или результат разбора.

| Статус | Что значит |
|--------|-----------|
| `EXACT` | найден в каталоге, должность, звание и «посмертно» совпадают |
| `DIFF` | найден, но должность, звание или «посмертно» отличаются |
| `OTHER_AWARD` | ФИО есть в этом указе, но с другой наградой |
| `NEW` | в каталоге нет такого ФИО в этом указе: неверная форма имени или запись не импортирована |
| `BAD_HEADER` | не распознаны номер или дата указа |

Как и окно импорта, отчёт берёт из каталога фамилии (неоднозначная косвенная форма,
«Лобанку» — Лобанок или Лобанк) и слова должностей: дефис переноса строки из указа
(«ком-плексу») убирается, если каталог знает слово слитно и ни разу не видел его
с дефисом. `--rules-only` отключает и то и другое.

Словари профессий берутся из настроек программы, другие можно указать через
`--dict-ru`/`--dict-by`. Для быстрых проверок есть `--filter <часть пути>` и `--limit <N>`.

## Настройки

Настройки хранятся в реестре: `HKCU\Software\Anatoli Nikitin\Kavaler`.

| Ключ | Что это |
|------|---------|
| `Database` | путь к базе SQLite |
| `DictionaryRU`, `DictionaryBY` | словари профессий для импорта (кнопка «Словари...» в окне импорта) |
| `YandexApiKey` | API-ключ Яндекс.Переводчика (меню «Правка → API-ключ Яндекса...») |

Ключ Яндекса можно задать и переменной окружения `KAVALER_YANDEX_API_KEY`, она важнее
настройки. В коде ключ не хранится.
